# Manuscript-ready method description (no empirical claims)

We extend EfficientRAG with query-dependent retrieval allocation while retaining its pretrained Labeler, token extraction, and Filter-based query reformulation. A deterministic analyzer assigns the initial retrieval width using question length, capitalized-span counts, relational markers, and comparison terms. These inexpensive surface features map to three configurable widths, initially 3, 5, and 8. The analyzer uses only the original question and requires neither an additional language model nor additional training.

After hop t, an evidence controller observes the number of returned passages, the number labeled CONTINUE, and the number of newly encountered passages and newly encountered CONTINUE passages. If at least 75% of results repeat previously encountered IDs and no new useful passage is found, the controller decreases K by two. Otherwise, it increases K by two when fewer than two useful passages are found or the useful fraction is below 0.25; it retains K in other cases. Width is bounded to [3,10]. These thresholds are initial policy hypotheses, to be selected using a development split and evaluated on held-out questions. The chosen width is passed directly to the next index search. No gold supporting-document identifiers, answer annotations, or future-hop observations are used by the allocation policy.

The controller does not create a stopping rule. In the recovered implementation, retrieval ends when no passage has a CONTINUE label or the four-hop safeguard is reached. The existing Filter constructs the next query whenever continuation is permitted. Consequently, the controller cannot rescue a hop in which all passages are labeled TERMINATE without changing the baseline stopping behavior; our implementation deliberately retains that limitation.

We define five controlled configurations: fixed K=5, fixed K=10, query-dependent initialization alone, per-hop adaptation from K=5 alone, and their combination. All configurations use the same evaluation examples, corpus, retriever, checkpoints, and maximum hop count. We measure supporting-document recall before and after Labeler rejection, the proportion of questions with all gold documents, retrieval calls, passage counts, elapsed search and pipeline time, and selected-K distributions. Merged document aliases are resolved only for evaluation. We also count questions whose K changes between hops, since variation across questions alone does not establish per-hop adaptation. Answer EM/F1 and token consumption require additional measured pipelines and are not reported here.

The available evaluation collection comprises 100 questions and a 991-passage corpus reconstructed from their distractor contexts. It is a small pooled-context retrieval experiment, not a full-Wikipedia retrieval benchmark. Historical checkpoint comparisons are recorded notebook results, and the delivered synthetic validation establishes software behavior only. No accuracy or efficiency improvement has yet been measured for the proposed method on the recovered real dataset.
